# SSH 提示符登录脚本

SSH 主机可以配置本机 JSON 文件，在 SSH shell 建立后按提示符逐步发送一行文本。它适合 shell 登录后的交互提示，例如登录后需要选择环境或输入应用层口令；SSH 握手阶段的密码、键盘交互认证和 MFA 仍由 SSH 认证流程处理。

## 配置

编辑 SSH 主机，在“提示符登录脚本”字段填写 JSON 文件路径。支持绝对路径、`~/` 和相对启动目录的路径。脚本路径保存在本机 SQLite 中，不会出现在 JSON 会话目录导出；导出 Xshell 原生会话时，带本地脚本的主机会列在跳过清单中。

```json
{
  "version": 1,
  "steps": [
    {
      "expect": "(?i)environment \\(dev/prod\\):",
      "send": "dev",
      "timeout_seconds": 30
    },
    {
      "expect": "(?i)password:",
      "send": "{{password}}",
      "timeout_seconds": 45
    }
  ]
}
```

每一步先等待 `expect` 正则匹配到终端新输出，再发送 `send` 并附加回车。省略 `timeout_seconds` 时默认等待 30 秒。`{{user}}` 会替换为 SSH 用户名；`{{password}}` 从当前主机或绑定的认证配置所引用的系统钥匙串读取。需要密码时必须先在应用中保存 SSH 凭据，不要把明文密码写进脚本。

脚本限制为最多 64 步、128 KiB；`expect` 最多 512 字符，`send` 每步最多 1024 字符并且必须是单行，超时时间为 1–300 秒。脚本加载和正则编译在连接前完成；某一步超时或发送失败会停止后续步骤，并在 pane 状态栏显示结果。pane 的 Shell 命令录制会生成同一版本的 JSON 格式，因此可在检查命令内容后复用为登录脚本。

旧的“SSH 连接后命令”仍可使用，但不能和提示符登录脚本同时配置。登录脚本只读取 shell 输出，不会执行本地程序，也不会自动输入或绕过 SSH 登录认证。
